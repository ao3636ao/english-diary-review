# ことばのノート — 英語日記・フレーズ復習

日本語を見て英語を考え、声に出してから自己採点する、個人用の英語表現ノートです。英語日記・日常フレーズ・ビジネス英語・練習例文を蓄積できます。

HTML / CSS / JavaScriptのみで動く、**ビルド不要の静的Webアプリ**です。サーバー処理・有料API・APIキー・ログインはありません。公開時の実行用パッケージも不要です。Android Chrome向けの画面、ホーム画面への追加、オフライン利用に対応しています。

日記と学習履歴は各端末のIndexedDBに保存します。アプリは学習データを外部送信せず、広告・アクセス解析・外部CDNを使用しません。リポジトリの学習内容は、すべて架空のテストデータです。

## まず使う

1. 公開したアプリをAndroid Chromeの**通常モード**で開きます。
2. 「追加」→「JSONファイルを選ぶ」で、端末内の `diary_pairs.json` を選びます。
3. 新規・重複・更新候補の件数を確認して「追加してバックアップ」を押します。
4. Chromeのダウンロード一覧で、バックアップJSONの保存を確認します。
5. 「ホーム」→「今日の学習をはじめる」で復習します。

実際の181文はリポジトリに入れず、完成後にご自身の端末から読み込んでください。最初から実データを表示したり、勝手にサンプルを登録したりすることはありません。

4. GitHubが表示する公開先をAndroid Chromeで開きます。

公開するのはコードだけです。実データや個人用JSONをコミットしないでください。`.gitignore` は `diary_pairs.json`、`english-diary-backup-*.json`、`personal-data/` を除外しますが、異なるファイル名まで自動保護する仕組みではありません。

- Chromeのメニューで「ホーム画面に追加」または「アプリをインストール」を選びます。対応環境では設定画面にもインストールボタンが出ます。
- 初回読み込みでService Workerがアプリ本体だけを保存し、以降はオフラインでも登録・復習・バックアップできます。

## 追加用JSON

1件のオブジェクト、または複数件の配列に対応します。ファイル・テキスト貼り付けの両方を受け入れ、ChatGPTの `json` コードフェンス付きテキストも読み込めます。

以下は**架空の例**です。

```json
[
  {
    "date_jst": "2026-10-18",
    "entry_type": "phrase",
    "category": "daily",
    "study_japanese": "架空の島で青い本を見つけた。",
    "english": "I found a blue book on an imaginary island.",
    "katakana": "",
    "explanation": "テスト用の架空の文章です。",
    "alternative_english": ["On an imaginary island, I found a blue book."],
    "tags": ["架空", "例"]
  }
]
```

ChatGPTには次のように依頼できます。

> アプリ追加用JSONで出して。study_japanese、english、date_jst、entry_type、category、katakana、explanation、alternative_englishを含めて。日付はYYYY-MM-DD。カタカナ発音を用意していない場合は空文字にして。

| 項目 | 扱い |
| --- | --- |
| `study_japanese` / `english` | 必須。空でない文字列 |
| `sentence_id` | 任意。指定IDを維持し、未指定ならUUIDを生成 |
| `entry_id` | 任意。日記や文脈のまとまりを識別。未指定ならUUIDを生成 |
| `sentence_no` | 日記セット内の文番号。数値または数値文字列。省略してもデータは読み込める |
| `date_jst` | 日本時間の日付。省略時は追加当日。重複判定の安定のため指定を推奨 |
| `entry_type` | 元の種類。既存の `diary` / `example` / `addition` を維持。新規で省略した場合は `phrase` |
| `category` | 学習カテゴリ。`diary` / `daily` / `business` / `practice` / `other` |
| `katakana` | 任意。未収録なら空欄。アプリでは生成しない |
| `explanation` | 任意。解説・補足 |
| `alternative_english` | 任意。文字列または文字列配列 |
| `tags` | 任意。文字列配列またはカンマ区切り文字列 |
| その他 | 出典情報などの追加フィールドを可能な限り保持し、バックアップにも含める |

主要テキストは各30,000文字まで、1ファイル・バックアップ全体は10MBまで、保存上限は20,000文です。全データをバックアップ可能なサイズか検証し、上限を超えた追加は保存前に止めます。

### 日記とフレーズの分類

`entry_type` と学習用の `category` は別の項目です。カテゴリを編集しても元の種類は維持します。カテゴリ未指定の既存データは次のように扱います。

| 元の種類 | 学習カテゴリ |
| --- | --- |
| `diary` | `diary`（英語日記） |
| `example` | `practice`（練習例文） |
| `addition` / その他 | `other`（その他） |

練習例文や補足を実際の日記に自動分類しません。未知のカテゴリも保持し、一覧や編集画面の選択肢に表示します。

複数文の日記は、各文に別の `sentence_id`、同じ `entry_id`、文順を表す `sentence_no` を指定します。「一覧」→「日記・まとまり単位」での表示と、日記セット復習に使います。文数は2文・3文・4文以上のいずれでも構いません。

以下は2文からなる**架空の日記セット**の例です。`sentence_id` は省略すれば自動生成されます。

```json
[
  {
    "entry_id": "fictional-diary-2026-10-18",
    "sentence_no": 1,
    "date_jst": "2026-10-18",
    "entry_type": "diary",
    "category": "diary",
    "study_japanese": "架空の島で青い本を見つけた。",
    "english": "I found a blue book on an imaginary island.",
    "katakana": ""
  },
  {
    "entry_id": "fictional-diary-2026-10-18",
    "sentence_no": 2,
    "date_jst": "2026-10-18",
    "entry_type": "diary",
    "category": "diary",
    "study_japanese": "その本には架空の地図が載っていた。",
    "english": "The book contained a fictional map.",
    "katakana": ""
  }
]
```

### 重複と更新

- 同じ `sentence_id` は同一レコードです。内容が異なる場合は更新候補にし、**チェックした候補だけ**更新します。現在の内容との比較も表示します。
- IDなしの場合は日付・カテゴリ・元の種類・日本語・英文を比較します。`entry_id` 指定時は文脈も区別します。同じ内容は重複、同一候補の補足などの変更は更新候補として扱います。
- 同じ英文でも異なる日付や明示的に異なるID・文脈なら保持します。
- 同一JSON内で同じIDに異なる内容がある場合は取り込みを止めます。
- 表現の追加・修正で学習履歴をリセットしません。部分更新では元の出典などの追加フィールドも維持します。

### 手入力・編集

「追加」→「手入力」から日本語・英語・発音・解説・別表現・カテゴリ・作成日・タグを登録し、プレビューで確認できます。

「一覧」では日本語・英語・別表現・タグ等を検索できます。表現を開くと編集・削除・その表現だけの復習ができます。削除には確認が必要で、対応する学習履歴も削除します。削除前のバックアップを推奨します。

## 復習と学習記録

1. 日本語を見て、英語を考えて声に出します。
2. 「答えを見る」で英文・カタカナ・解説・別表現を確認します。
3. 「覚えた」または「もう一度」で自己採点すると、保存完了後に次へ進みます。

### 日記セット復習（英語日記の標準）

「復習の単位」の標準設定は **日記はセット、フレーズは1文** です。過去の設定に復習単位がなくても、この標準設定で動きます。ホームの「日記セットを復習」、または復習画面のかんたんモード「日記セット復習」から、日記だけを始めることもできます。一覧の各日記にもセット復習ボタンがあります。

- `entry_type` または `category` が `diary` の文を、同じ `entry_id` ごとにまとめます。通常の例文・補足表現は1文のままです。
- 日本語を日記全体で表示し、「答えを見る」で対応する英文・登録済みのカタカナ発音・解説を文順どおりに表示します。発音表記は生成・変更しません。
- `sentence_no` を数値順に並べます。番号がない・不正な文は番号付きの文の後に置き、番号なし・同番号の文は `sentence_id` の自然順（例：2→10）で安定表示します。元の番号やレコードは書き換えません。
- ランダムにするのはセットの順だけです。長い日記が先に選ばれやすくなることも、セット内がシャッフルされることもありません。
- 未学習・苦手・カテゴリ・期間で絞り込む場合、条件に合う文を含む日記全体を出題します。文脈を保つため、セット内の他の文も表示・復習します。
- 「セットを覚えた」「セットをもう一度」で、表示中の各文の履歴に1回ずつ記録します。一部だけ結果が違うときは「文ごとの操作」を開き、「この文だけ判定を変える」で指定します。セットの記録は1つのトランザクションで保存し、途中失敗時は全体を巻き戻します。
- 「セットを音読 ＋1」は各文の音読回数を1回ずつ加算します。各文の現在の回数は折りたたみ中も表示します。「文ごとの操作」では回数の加算・修正・1文だけの音声再生ができます。「日記を読み上げる」では音読回数は増えません。

従来どおりに学ぶときは「復習の単位」→ **1文ずつ復習（従来のモード）** を選びます。選択は保存され、日記も1文ずつ出題されます。

学習履歴は引き続き各 `sentence_id` に保存します。セット専用の別履歴は作らず、既存の正誤・音読・習得状態を保持します。IndexedDBとバックアップのスキーマバージョンは **1のまま** です。設定に任意の `filters.unit`（`auto` / `diary-set` / `sentence`）を追加しただけで、旧バックアップも復元できます。

インストール済みPWAでは、更新通知が出たら「更新する」で新しい画面へ切り替えてください。アプリ本体のキャッシュ更新でIndexedDBは削除しません。

全問ランダム、日記、日常、ビジネス、練習例文、未学習、前回間違えた問題、苦手優先、日付順、指定期間に対応します。カテゴリ・復習状態・期間は組み合わせ可能です。1回のセッションでは同じ問題を重複出題しません。途中で条件を変えた場合、新しく復習を開始すると適用されます。

「苦手」は前回「もう一度」、または不正解回数が正解回数を上回る問題です。「覚えた」で習得状態を「習得」、「もう一度」で「学習中」にします。自己評価であり、自動的な意味判定は行いません。

英文ごとに正解・不正解回数、最終学習日時・判定、習得状態、音読回数を保存します。ホームに最近の復習、記録画面に総数・学習済み・未学習・自己採点の累計正解率・苦手数・音読回数・カテゴリ別の集計を表示します。

### 音声と音読

Web Speech APIで**端末内の英語音声（`localService === true`）だけ**を選びます。オンライン音声を使って学習データを外部送信することを避けます。対応する音声がない場合は案内を出して読み上げません。必要に応じてAndroidの設定で英語のオフライン音声を追加してください。

速度は設定で0.5〜1.5倍に変更できます。「英文を読み上げる」は何度でも押せます。再生だけでは音読回数は増えません。自分で音読したときに「音読 ＋1」、または回数を入力して「回数を保存」を押してください。

## 保存・バックアップ

追加・編集・カテゴリ変更・自己採点・音読回数・設定は、IndexedDBのトランザクションが完了してから成功表示します。容量不足や保存エラーを成功扱いにしません。取り込み・復元は全体を検証し、保存中に失敗した場合は一括で巻き戻します。別タブの更新も検出し、古い状態での上書きを防ぎます。

「追加してバックアップ」は次の順に動きます。

1. 内容・重複・選択した更新を検証
2. IndexedDBに保存し、完了を確認
3. 全データを再取得してバックアップJSONを作成
4. ダウンロードを要求し、結果と全体件数を表示

手動バックアップはヘッダー、または「設定」→「全データをバックアップ」から行えます。ファイル名は日本時間で `english-diary-backup-2026-10-18-210001.json` のように日時が付きます。

スキーマバージョン、すべての表現と追加フィールド、カテゴリ、学習履歴、音読回数、設定、データ更新日時、バックアップ作成日時を含めます。

**ダウンロードの要求は、端末への保存完了を意味しません。** Chromeのダウンロード一覧で実ファイルを確認してください。自動ダウンロードが始まらない場合は通知の「再ダウンロード」を押せます。直前のファイルは設定画面からも再ダウンロードできます。

最終バックアップ**作成**日時と、作成後の更新の有無を表示します。バックアップに失敗しても保存済みの追加データは維持し、その状態を明示します。

バックアップは暗号化していません。個人情報を含むファイルとして、安全な場所に保管してください。顧客情報・非公開案件情報・社内機密情報の登録は想定していません。

## 機種変更と復元

1. 元の端末で全データをバックアップし、保存完了を確認します。
2. 新しい端末にファイルを安全に移します。
3. 同じアプリの「設定」→「バックアップJSONを選ぶ」で読み込みます。
4. 内容を確認し「既存データを上書き」または「既存データと統合」を選びます。キャンセルも可能です。
5. 復元後に件数と学習履歴を確認し、新しいバックアップを作ります。

上書きは確認画面が必須で、表現・履歴・音読・設定をまとめて置き換えます。統合では内容の競合時に端末とバックアップのどちらを採用するか選べます。設定の取り込みは任意です。

履歴は**更新日時が新しい側の履歴全体**を1件ずつ採用し、回数を足しません。同じバックアップを繰り返し統合しても二重加算しません。同時刻は選択した側を優先します。別端末で並行して学んだ回数を合算する機能ではありません。端末の時計を正しくし、統合前のデータも残してください。

不正JSON、未対応バージョン、重複ID、対応問題がない履歴、不正な回数・日時・設定は復元前に拒否します。`diary_pairs.json` の配列はバックアップではないため「追加」から読み込んでください。

## データ消失のリスク

通常はブラウザ終了や再起動後もデータは残りますが、ブラウザのデータ削除、シークレットモードの終了、ストレージの整理、故障、URL・プロファイル変更などで使えなくなる可能性があります。

設定から `navigator.storage.persist()` を要求できますが、許可はブラウザ次第であり、故障や手動削除は防げません。**端末内の保存だけに依存せず、追加後・学習後・機種変更前にバックアップしてください。**

## 開発・テスト

Node.js 22以降で、ビルドなしで起動できます。

```sh
cd english-diary-review
npm run start
```

開発サーバーはポート4173を使い、ルートと `/english-diary-review/` に対応します。既定ホストは127.0.0.1です。クラウドでの起動コマンドは次のとおりです。

```sh
npm run start -- --host 0.0.0.0 --port 4173
```

操作可能なプレビューには、実行環境のポート転送を開発サーバーの4173番ポート・パス `/` に接続する必要があります。HTMLファイル単体のプレビューでは、相対パスのCSS・JavaScript・画像が配信されない場合があります。利用者の端末のlocalhostはクラウド上のサーバーとは異なるため、外部から開くURLには実行環境が発行した転送URLを使います。

公開用ファイルだけを配信し、個人用JSONや `.git` は配信しません。

テスト用依存関係だけを導入します。

```sh
npm ci --ignore-scripts
npm test
npm run test:e2e
# または、両方を実行
npm run test:all
```

E2EはPlaywrightを使います。`/usr/bin/chromium` がある場合はそれを使い、別の場所の場合は `CHROMIUM_PATH=/path/to/chromium npm run test:e2e` を指定できます。システムのChromiumがない場合は `npx playwright install chromium` でPlaywright用ブラウザを導入してください。

クラウドではnpmキャッシュを `--cache /workspace/.cache/npm` に指定できます。アプリ本体の利用・GitHub Pagesへの公開には `npm install` は不要です。

| ファイル | 役割 |
| --- | --- |
| `src/core.js` | 検証・重複判定・出題・バックアップ統合 |
| `src/db.js` | IndexedDB・一括保存・同時更新の検出 |
| `src/app.js` | 画面操作・保存・ダウンロード・端末音声 |
| `src/views.js` / `styles.css` | 日本語UI・レスポンシブデザイン |
| `sw.js` / `manifest.webmanifest` | オフライン・インストール |
| `tests/fixtures.js` | 130日記・48例文・3補足からなる架空の181文 |

アプリ更新時は変更した静的ファイルを `sw.js` の `FILES` に含め、`CACHE` のバージョンを更新してください。IndexedDBはキャッシュ削除で消しません。DB構造を変えるときはバージョン移行とバックアップ互換性を別途実装してください。
